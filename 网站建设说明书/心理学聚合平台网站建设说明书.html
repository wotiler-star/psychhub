一、文档目的与范围

1.1 目的

本说明书是「心理学垂直网站项目」的建设执行蓝图。它把《全球心理学网站 TOP50 调研分析报告》中的市场结论，转化为可落地的产品功能、信息架构、技术选型与开发排期，供产品、设计、研发、运营团队对齐共识。

1.4 建设原则（强制约束 · 最高优先级）

以下原则为项目建设的刚性底线，任何技术方案与排期均不得违反：
  • ① 前后端必须分离开发：前端（界面与交互）与后端（业务逻辑与数据）作为两个独立工程、独立仓库、独立部署。双方仅通过标准化 API（RESTful / GraphQL + OpenAPI 契约）通信；禁止服务端模板直出页面、禁止在视图层编写业务逻辑、禁止前后端代码耦合在同一工程。
  • ② 技术栈选型四原则——先进 · 合理 · 科学 · 实用：
    • 先进：优先采用当前主流、活跃演进的现代技术（如 TypeScript 全栈、云原生、声明式 UI），不接受已被行业淘汰或停止维护的方案；
    • 合理：技术匹配业务规模与团队能力，不为「先进」而过度设计（如小流量阶段不盲目上重型微服务）；
    • 科学：遵循关注点分离、单一职责、可测试性等工程化基本原则，架构决策有依据、可解释；
    • 实用：以「可交付、可运维、可扩展」为终判标准，文档、测试、监控一并交付，不堆砌无法落地的概念。
  • ③ 工程化基线（默认要求）：类型安全（TypeScript）、容器化（Docker）、自动化测试与 CI/CD、可观测性（日志 / 监控 / 告警）为必备项，不视为可选项。

二、项目定位与产品目标

2.1 一句话定位

「全球心理学资源的中文入口 + 专业分层的聚合导航平台」——对大众是可信的心理科普与自助入口，对学生是心理学学习资料库，对从业者是工具、量表与行业情报台。

2.2 产品原则（区别于自媒体/链接农场）

  • 可信优先：所有内容带专业审核标识与溯源，对标 Verywell 的 Medical Review Board。
  • 结构化优先：知识以词条/图谱形式结构化存储，利于用户检索与 AI 引用（抗 SEO 冲击）。
  • 聚合 + 深加工：不做全文转载，做「摘要 + 溯源链接 + 中文化解读」，沉淀自有结构化资产。
  • 分层服务：同一平台服务大众 / 学生 / 从业者三类人群，通过账号体系做个性化分发。

• 找量表、工作表、执业 SaaS 选型

五、功能需求规格（模块清单）

优先级：P0 一期必做（MVP 核心）；P1 二期增强；P2 三期生态。

M0 全球心理学网站 / 资源导航目录P0一期 · 对标 findahelpline + 本报告数据

把《TOP50 调研报告》的 50+ 站点作为首批种子数据，扩展为「全球心理学资源中文导航」。

  • 资源分类：按调研六大赛道（媒体/执业SaaS/咨询/机构/测评/冥想）+ 主题标签多重归类
  • 检索与筛选：支持关键词、国家/地区、类型、语言、是否免费筛选
  • 资源详情页：简介 + 核心功能 + 流量量级 + 适合人群 + 直达外链（摘要+溯源，不全文转载）
  • 收录机制：管理员后台录入 + 用户提交（需审核），支持「收录-认证」两级状态
  • 数据看板：按赛道/国家统计收录量，支撑持续扩充
M1 心理学资讯 / 研究速递聚合P0一期 · 对标 APA / 顶刊
  • 资讯流：聚合全球心理学新闻、研究进展、行业动态（RSS + 编辑精选）
  • 研究速递：顶刊（如 Frontiers in Psychology）论文摘要中文化、加「通俗解读」标签
  • 订阅推送：注册用户可按主题订阅（焦虑/抑郁/ADHD…）
M2 结构化心理学知识库P1二期 · 对标 SimplyPsychology
  • 词条类型：理论、流派、代表人物、核心概念、心理量表，相互关联成知识图谱
  • 词条规范：定义 + 起源 + 关键研究 + 应用 + 参考资料（可引用格式）
  • SEO/AI 友好：结构化数据（Schema.org），利于被搜索引擎与 AI 直接引用
  • 编辑流程：投稿 → 专业审核 → 发布，带「已审校」标识
M3 心理测评中心P0一期起步 / 二期扩量 · 对标 16Personalities
  • 首批量表：PHQ-9（抑郁）、GAD-7（焦虑）、大五人格、压力自评等公开版权量表
  • 施测-计分-解读闭环：在线作答 → 自动计分 → 生成通俗结果报告
  • 结果分享：生成可视化结果卡（社交裂变），但带「非诊断」声明
  • 个人档案：登录用户保存历史测评，生成趋势曲线（留存钩子）
  • 版权合规：商业量表（MBTI 正版、SCL-90 修订版）须取得授权后上线
M4 求助资源库（热线 / 公益 / 低价咨询）P0一期 · 对标 findahelpline + Mind UK
  • 按国家/地区/语言检索危机热线、公益组织、低价咨询渠道
  • 危机干预组件：全站高危内容页（如自杀、自伤）置顶 988 式求助提示

七、内容策略

  • 种子内容：直接导入《TOP50 调研报告》的 50+ 站点作为资源目录首批数据；APA / Mind UK / SimplyPsychology 的开放内容做中文化摘要。
  • 原创中文化：顶刊研究速递、理论词条、测评解读——强调「循证 + 易懂 + 带溯源」。
  • 专家供稿：邀请持证心理咨询师/研究者供稿，对标 Psychology Today 专家博客模式。
  • 更新频率：资讯每日更新；知识库词条每周 5-10 条；测评中心随授权扩充。
  • 结构化优先：所有内容以可被 AI/搜索引用的结构化数据产出，对抗 AI 搜索对媒体的冲击。

八、交互与视觉设计规范

8.1 设计语言

  • 调性：专业、可信、温和（心理学场景需降低焦虑感）。主色沿用本说明书与调研报告的靛蓝 #4f46e5，辅以青色 #0ea5e9。
  • 字体：中文「思源黑体 / 苹方」，正文 15px，行高 1.75，保证长文可读。
  • 留白：内容站需大留白与清晰层级，避免信息过载（区别于链接农场观感）。

8.2 关键交互

  • 全局搜索 + 多维筛选（资源/测评/求助通用组件）。
  • 测评作答分步进度条，结果页「生成分享卡」一键转发。
  • 危机干预组件：任何含自伤/自杀关键词的页面自动置顶求助条。
  • 全站响应式（移动端优先，测评与求助在移动端使用频次最高）。

九、技术架构建议

9.1 总体架构（强制前后端分离）

架构红线：前端工程与后端 API 服务独立开发、独立仓库、独立部署，二者仅通过标准化 HTTP API（RESTful + OpenAPI，或 GraphQL）通信。前端不直连数据库、不写业务规则；后端不负责页面渲染。采用 API-First：先用 OpenAPI/Swagger 定义接口契约，前后端并行开发。

前端工程
（Web 客户端）		Next.js（React 18）+ TypeScript + Tailwind CSS + 组件库（shadcn/ui 或 Ant Design）页面渲染（SSR/SSG 兼顾 SEO）、交互、状态管理；仅消费后端 API；独立仓库 / 独立 CI-CD / 独立部署（Edge 或 Node 运行时）；静态资源走 CDN

9.2 非功能性要求

  • 首屏加载 < 2s；Lighthouse SEO/可访问性评分 ≥ 90。
  • 结构化数据（Schema.org / JSON-LD）覆盖资源、词条、测评、FAQ。
  • 支持 i18n（中文为主，预留英文/多语言以承接全球资源）。
  • 后台 CMS 支持内容审核流（投稿→审校→发布）。

十、数据安全与合规风控

高优先级风控：心理内容属敏感领域，合规是平台生死线，须在 MVP 阶段即内建。
  • 内容免责：所有科普/测评页加「非医疗建议、不构成诊断」声明；测评结果须标注「仅供参考」。
  • 危机干预：高危页面置顶求助热线，建立与 988 / 当地热线联动的应急机制。
  • 量表版权：仅上线 PHQ-9、GAD-7 等公开授权量表；MBTI、SCL-90 等商业量表须取得正式授权。
  • 隐私保护：测评/账户数据加密存储，明确告知用途，符合个人信息保护法；不向第三方出售数据。
  • 聚合外链：遵守 robots 协议与版权规范，采用「摘要 + 溯源链接」，不全文转载。
  • 审核机制：建立专业审核委员会（对标 Verywell Medical Review Board），内容发布前审校。
  • 避免诊疗：本期不做在线问诊/开药，咨询师目录仅做「转介」，规避互联网诊疗资质风险。

十一、运营与增长策略

  • 测评裂变：结果分享卡（对标 16Personalities）是零成本获客核心抓手。
  • SEO / 结构化：长尾词条 + JSON-LD，承接 AI 搜索流量（抗传统 SEO 波动）。
  • 专家与机构合作：邀请供稿、收录优质机构，建内容与资源双边。
  • 主题频道深耕：ADHD/焦虑等垂直人群运营，复刻「小切口百万流量」。
  • 公益背书：与 Mind UK / 988 式资源联动，提升可信度与公关安全。
